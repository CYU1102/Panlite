## 本地候选迭代的性能对照

对照的是本轮初始与最终候选，**不是已发布的 0.2.2**。同机同样本下，目录数据库查询 p95 为 44.32ms、完整词法/语义尾部检索为 231.79/391.02ms，均未超过 20% 复核阈值。合作任务取消到队列空闲首次对照为 23.27ms，随后冻结快照重测为 26.94ms，比初始 20.33ms 增加 6.61ms（32.51%），须保留复核。固定五次样本受本地调度与I/O影响，未确定为代码回归，不据此承诺加速，也不删掉超阈值结果。

## 首轮干净 CI 发现与修复

首轮提交 `c9c5fc29bbc92b438e7757964a6f1a1ecb81c222` 的 Windows CI 通过依赖安装、引擎、lint及构建，随后回归发现五项失败（另有一个未安装选配 Poppler 的集成用例跳过），因此未进入安装阶段。

- Windows `RUNNER~1` 短路径与 `realpath` 长路径混用，导致快照把托管 AI 附件判为外部，并漏报缺失附件。已统一现存与缺失尾部的路径身份，同时保留受管树链接拒绝策略。
- 下载结果按设计返回物理路径，测试却按原始短路径断言或注入失败。已规范化测试路径，新增真实目录别名验证；还修复了别名缓存根可能绕过“目标不能位于续传缓存内”的实际保护缺口。
- AI 文件哈希在 ReadStream 的 `end` 返回时句柄尚未关闭，快速解析流程后清理可能遇到 `ENOTEMPTY`。已等待 `close` 后结束成功或失败，新增稳定的延迟关闭回归；没有靠删除重试掩盖未完成读取。

修订仍需新的全量及 CI 证据，不能沿用首轮失败构建作为发布通过记录。

第二轮 CI 已通过快照与 AI 修复；剩余三个下载断言进一步确认 Node 的 JavaScript `realpathSync` 可能保留 Windows 短名，而异步原生实现展开长名。测试现使用 `realpathSync.native` 保持相同路径身份。另通过真实 8.3 实验提前修复安装验收脚本将 PowerShell 长名 profile 与 Node 短名 TEMP 误判为越界的问题，仍保留用户目录、GUID 目录及链接拒绝检查。
